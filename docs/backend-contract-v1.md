# Backend contract v1 — design prerequisite

Prepared 2026-11-18. **Design only; no service, cloud mutation, or training is established by this document.** This settles Phase 3/4 interfaces while Phase 2 continues. Inputs: [design](design-v2.md), [upload contract](data-contracts/weekly-pricing-v1.md), [preflight](deployment-preflight-2026-11-17.md), [research protocol](model-protocol-v1.md). Routes below are our proposed API, not Azure APIs.

## Boundary and ownership

- One same-origin SPA/FastAPI Container App (Consumption, min=0/max=1), one fixed manual training Job, private Blob storage, and Azure Table metadata. Deploy a code-only public GHCR image pinned by digest; model bundles and raw history stay in private Blob storage, including the licensed OJ source, which must never enter the public image. No shared SQLite or API-process background training. Reuse the personal Central US resources identified in private deployment notes; explicitly bind the personal subscription on every Azure client/command. The employer CLI default is forbidden; spendingLimit remains On.
- Anonymous and uninvited accounts read only curated sample IDs from `/samples`. All uploads, aggregates, models, plans, reviews, and published pricebooks stay private to their workspace. Publication means **Demo ledger**, never public sharing or an ERP update. A sample must have an independently curated allowlist/manifest; an upload cannot set `public=true`.
- Resolve identity by `(issuer, uid)` and load an enabled server-owned membership on every private request. Analyst: upload/train/compare/edit/submit. Reviewer: read/review/publish. Owner: membership/budget administration and publish; editing/training/reviewing additionally requires the relevant capability. Viewer has no private access unless explicitly given workspace read access. Resource ownership is workspace membership plus action permission, never possession of a guessed ID.
- V1 policy choice: reviewer or owner may publish; each approving reviewer must differ from the proposal author and every executable editor recorded in that revision. Owner cannot bypass that rule. Rejected/excluded rows terminate scope with reasons; approved feasible holds are exported. Every executable edit invalidates approval for the whole plan.

## Authentication and HTTP rules

- The browser signs in with Firebase email/password and sends an ID token as `Authorization: Bearer …`; retain it in session memory, not URLs or business exports. English/Chinese sign-in, expired-session, forbidden-action, and validation messages use stable server error codes. On expiry, preserve safe unsent form state and server drafts; after sign-in, reload current permissions/revisions before retrying with the original idempotency key. There is no public privileged password or client role selector.
- Verify signature against cached public certificates with `google.oauth2.id_token.verify_firebase_token(token, request, audience=project_id)`; explicitly validate issuer `https://securetoken.google.com/{project_id}`, nonempty subject, expiry, and issued-at. Every private request requires a valid token, enabled server-side membership/role, and token `auth_time` after the application's revoked-before timestamp. Design policy: ordinary analyst/reviewer edits use these checks without a separate 15-minute reauthentication gate; an owner-configured recent-auth guard for train/review/publish may require `auth_time` within 60 minutes. Owner membership/budget changes require authentication within 15 minutes. Provider revocation/disable checks are **not** implied by certificate verification; Firebase Admin `check_revoked=True` needs a separately proven credential path. [Google verifier](https://google-auth.readthedocs.io/en/latest/reference/google.oauth2.id_token.html), [Firebase Admin](https://firebase.google.com/docs/reference/admin/python/firebase_admin.auth).
- Reuse the inspected [healthcare certificate-cache/issuer pattern](https://github.com/rockyzl/revenue-cycle-agent/blob/main/app/portal/auth.py); copy only the verifier boundary. Its portal tests mock authentication, so they do not verify live Firebase sign-in. No seeded account/role mapping transfers to pricing. Membership provisioning initially uses an owner-operated administrative path, not public signup escalation.
- JSON rejects unknown fields/nonfinite numbers; server creates IDs, actors and UTC timestamps. Mutable resources return opaque ETags; mutations require `If-Match` plus relevant revision/generation. Create/action POSTs require `Idempotency-Key`, scoped to workspace+actor+route, storing canonical request hash and result; same key with different bytes is `409`. Matching retry returns the original operation after current authorization is rechecked.
- Errors: `{error:{code,message_key,request_id,fields?,current_revision?}}`; `401` invalid/expired identity, `403` forbidden action, `404` unavailable/cross-workspace resource, `409` state/idempotency conflict, `412` stale ETag, `413` bytes exceeded, `422` invalid/admission input, `429` quota/busy, `503` disabled/unavailable dependency. Do not expose raw provider exceptions, tokens, passwords, file contents, or signed URLs in logs. Private responses use `Cache-Control: no-store`; lists use bounded opaque cursors (default 50, maximum 100).

## Minimal routes and payloads

All private paths start `/api/v1/workspaces/{workspace_id}`; abbreviations below omit that prefix. Read authorization applies to every nested object and artifact reference.

| Route | Request → result / permission |
|---|---|
| `GET /api/v1/samples[/{id}]`; `GET /api/v1/me` | Public curated manifests; authenticated principal, memberships, allowed actions and effective limits. |
| `POST /datasets`; `GET /datasets/{id}` | Stream `text/csv` bytes → immutable dataset ref, validation/audit summary; analyst upload, members read. |
| `POST /snapshots`; `GET /snapshots/{id}` | `{dataset_id,cutoff}` → cutoff/version, catalog scope hash/count, analysis refs. |
| `GET /snapshots/{id}/catalog`; `GET /snapshots/{id}/series/{row_id}` | Paged catalog / bounded history, provenance, gaps and explicit unavailable inputs. `row_id` is an opaque encoding of canonical series identity. |
| `POST /training-runs`; `GET /training-runs/{id}` | `{snapshot_id,pipeline_version}` → `202` Run + status URL; analyst, active server-allowlisted pipeline only. |
| `POST /training-runs/{id}/cancel`; `POST /training-runs/{id}/reconcile` | Persist cancellation or resume bounded dispatch/status reconciliation; author/owner cancel, authorized analyst/owner reconcile. GET never starts work. |
| `GET /models/{id}` | Model manifest, actual evaluation/qualification evidence and allowed uses; no downloadable executable checkpoint. |
| `POST /plans`; `GET /plans/{id}`, `/plans/{id}/rows`, `/plans/{id}/events` | `{snapshot_id,model_id?,business_inputs_ref?,rules_ref,period:[4 weeks]}` → draft; analyst creates, members read. |
| `POST /plans/{id}/revisions` | `{base_revision,changes:[{row_id,row_etag,price_schedule?,disposition?,reason}],input_refs?}` → new draft revision; analyst, plan ETag required. |
| `POST /plans/{id}/compare` | `{revision}` → bounded comparison operation/result tied to frozen inputs; analyst. Slow computation must use a durable bounded worker, not BackgroundTasks. |
| `POST /plans/{id}/submit` | `{revision,proposal_hash}` → immutable submitted snapshot after full scope validation; analyst. |
| `POST /plans/{id}/reviews` | `{revision,proposal_hash,review_generation,rows:[{row_id,row_etag,action,reason?}]}` → events/new generation; reviewer, at most 40 rows per atomic request. |
| `POST /plans/{id}/publish`; `GET /pricebooks/{id}` | `{revision,proposal_hash,review_generation,destination:"demo_ledger"}` → same immutable pricebook on retry; reviewer/owner publish. |
| `GET /pricebooks/{id}/pricebook.csv`; `GET /pricebooks/{id}/coverage.csv` | Authorized streams from immutable artifact refs; all precision/unit/provenance metadata retained. |

V1 admits only the existing bounded weekly CSV; Parquet, raw transactions, scripts, model pickle/joblib uploads, arbitrary URLs/images/commands/environment overrides are rejected. Enforce 10 MiB while streaming and all [parser limits](data-contracts/weekly-pricing-v1.md), including 100,000 observations/2,000 series. Training separately validates **≤300 series and ≤40,000 expanded training examples** before reservation and again in the worker; import success is not a capacity promise. Admission failure still permits inspecting the dataset.

## Shared immutable schemas and model seam

- `ArtifactRef = {id,sha256,bytes,media_type,schema_version}`; internal metadata additionally resolves a server-owned container/key/version. A caller never supplies a filesystem path, SAS URL, or arbitrary Blob key. Create-only block blobs named by workspace/run/content identity are immutable application versions; record provider version IDs when available without assuming account-wide versioning is enabled. Verify hashes on consumption; no overwrite or user-uploaded checkpoint deserialization.
- `Dataset = {id,workspace_id,created_by,raw_ref,dataset_version,schema_version,validation_status,counts,provenance_ref}`. `Snapshot = {id,dataset_id,dataset_version,cutoff,snapshot_version,scope_ref,analysis_ref}`. Blob stores canonical observations, panels, catalogs, analysis, candidate arrays, manifests and exports; Table stores small metadata, status, counters and review rows. An upload's source-asserted currency/unit never becomes independently verified.
- `Run = {id,workspace_id,requested_by,snapshot_id,pipeline_version,state,phase,completed_tasks,total_tasks?,started_at?,finished_at?,execution_name?,artifact_refs?,error_code?,etag}`. Progress reflects measured tasks; completion does not imply scientific validation or publication permission.
- `Model = {id,run_id,snapshot_version,origin,protocol_hash,code_hash,lock_hash,image_digest,candidate_id,evaluation_ref,qualification_ref,checkpoint_ref_internal,review_status,allowed_uses}`. Server adapters call current `fit_model`, `price_qualification`, and `predict_scenarios` in [models.py](../src/pricing_engine/models.py); neither HTTP handlers nor imports fit models. Actual cutoff/origin and qualification lineage must match the requested scenario.
- Scenario inputs are every origin-visible `series_id × four weeks`, with explicit positive `price` and `feature_ad ∈ {0,1,null}`; OJ reference uses cutoff 160 and source weeks 161–164, never invented dates. Outputs retain `prediction_status`, price/ad support, qualification reasons, `interval_status`, and units/provenance. Unsupported rows remain in coverage as fallback/hold/manual-review, not fabricated elasticity or an empty successful plan.
- Operational retraining runs a previously reviewed, fixed runtime pipeline on an authenticated authorized request and saves **unreviewed** results. Its allowed-use/evidence policy must be validated before deployment; price publication still needs the separate human review below. Current OJ research smoke/selection/confirmation/refit approvals remain governed by the research protocol; this API neither invokes nor silently relaxes those execution gates.

## Persistence and concurrency

Use separate tables for identities, workspace metadata, training control, and plan decisions. The worker has no identity/role or review/publication table permissions; metadata access is read-only, with the API registering model references after verifying completed result manifests. Azure Table authorization is table-scoped, not per workspace/partition; application access checks remain mandatory. [Table authorization](https://learn.microsoft.com/en-us/azure/storage/tables/authorize-access-azure-active-directory).

| Table / partition | Authoritative records |
|---|---|
| `PricingIdentity` / hashed issuer+uid | Enabled flag, revoked-before, memberships/capabilities and policy version; no passwords. |
| `PricingMetadata` / workspace ID | Dataset/snapshot/model metadata and operation idempotency references; large content in Blob. |
| `PricingControl` / `training` | Singleton slot+generation, settings, UTC-day global/user quota rows, Run rows, dispatch intent, training idempotency rows; all admission conditions share this partition. |
| `PricingPlans` / workspace+plan ID | Head ETag/current revision/review generation/state, small proposal and review rows, append-only events, publication and idempotency rows. Workspace listing is a rebuildable index, never authority. |

Azure limits a string/binary property to 64 KiB, an entity to 1 MiB/252 custom properties; cap our scalar text/comments well below that and put large JSON in Blob. A transaction is limited to **100 entities/4 MiB in one table+partition**, one operation per entity; no transaction spans Blob and Table. [Data model](https://learn.microsoft.com/en-us/rest/api/storageservices/understanding-the-table-service-data-model), [transactions](https://learn.microsoft.com/en-us/rest/api/storageservices/performing-entity-group-transactions).

Write complete immutable blobs/staged rows first, then CAS the authoritative head/reference after hash/count checks. Crashes may leave unreferenced objects; they cannot expose half-ready datasets or plans. Garbage collection must preserve referenced versions and active operations. Use opaque/hash Table keys rather than raw `series_id` (which can contain forbidden key characters). Explicit state fields represent null/missing, since Table omits null properties.

All row writes compare ETags. Every proposal edit additionally CAS-updates the plan head/revision; every review updates the row projection, appends its event, and CAS-increments head `review_generation` in the same transaction. A 40-row review needs at most 82 entities (40 projections, 40 events, head, idempotency); enforce both count and serialized-byte limits. UI “all filtered” must send explicit resolved IDs/counts, chunk with visible progress, and never claim cross-chunk atomicity. Revision staging may span batches; only a validated manifest/head flip makes it current.

## Durable training admission and dispatch

Initial owner-controlled settings: training kill switch; global daily starts ≤3, per-user daily starts ≤2 (UTC); one global slot; runtime ≤600 seconds, soft drain at 480; retries=0. CPU/memory and tighter limits depend on measured model admission. Quotas count reserved dispatches including failures/ambiguity; no refund enables a retry loop. Upload bytes/storage retention and request-rate quotas also need finite owner settings. Limits are usage controls, not a dollar hard cap.

1. Validate access, immutable input and pipeline admission. In **one conditional control-partition transaction**, compare settings/slot/quota ETags, reserve the singleton generation and quota, create Run and idempotency rows. Busy is `429`; no second admitted queue item in v1. The durable accepted state is `queued`.
2. A request-bound dispatcher CAS-records `dispatching`, intent/time and the fixed job's prior execution names before one start call. The fixed worker reads the reserved run from Table; no per-request template is needed. Never let SDK/proxy retries repeat a mutating start after an uncertain response. Request loss before intent can safely resume dispatch; after intent it requires reconciliation.
3. The worker obtains its platform `CONTAINER_APP_JOB_EXECUTION_NAME`, verifies the reserved generation/input hashes, and atomically claims both Run and slot before preprocessing/fitting. Claiming is permitted only for that outstanding dispatch, never an idle/queued slot; old execution names cannot claim again. A duplicate execution that loses CAS exits without fitting. Record the binding and heartbeat; the claim is never reassigned merely because its timestamp expired. [Built-in job identity](https://learn.microsoft.com/en-us/azure/container-apps/environment-variables).
4. State flow: `queued → dispatching → running → succeeded | failed`; uncertain start is `dispatch_unknown`; cancellation is `cancel_requested → cancelling → cancelled`; timeout becomes `timed_out` only after execution termination is confirmed. `dispatch_unknown` can reconcile to running or a proven failed dispatch. Store sanitized failure and partial evidence; incomplete results never qualify for pricing.
5. The initiating request performs bounded dispatch; later explicit reconcile POSTs resume control work after scale-to-zero/crash. Reconcile the recorded operation/execution list and worker binding; a timeout is not proof start failed. With an unknown outcome, retain the slot and show a recoverable blocked status, **never blindly reissue start**. Historical missing executions alone do not prove no active work.
6. A reconciler releases slot by CAS only after all executions attributable to that dispatch are terminal (including any losing duplicate) and artifacts/status are finalized. Worker heartbeat loss or successful artifact writing alone is insufficient. Persist cancellation before issuing stop; wait for termination. Unknown starts remain fenced until positive reconciliation or an owner recovery procedure proves quiescence. New admissions cannot let an old execution claim a newer run.

`parallelism=1` controls replicas **within an execution**, not global overlapping executions; slot enforcement remains essential. Start permission permits template overrides at Azure's boundary, so the API identity is trusted and the public route cannot proxy ARM. [Job configuration and permissions](https://learn.microsoft.com/en-us/azure/container-apps/jobs).

## Review and publication invariants

- Freeze `PlanRevision = {revision,author_uid,editor_ids_ref,scope_ref,period,input_refs,model_ref,rules_ref,proposal_hash,comparison_ref}`. Every scope row retains candidate/hold comparators, constraints, feasibility reasons, solver status, chosen schedule and disposition. Missing cost disables contribution optimization; scenario cost remains scenario. A hard-rule-violating hold cannot be approved as executable.
- Submit requires a completed comparison for that exact revision and one disposition per scope row. Review actions are `approve_change`, `approve_hold`, `request_revision`, `reject`, `exclude`; the latter three require a reason. A request for revision remains unresolved. Rejection/exclusion is resolved but nonexecutable. Approval binds actor+proposal hash+revision+row hash; a reviewer suggested price is only a comment until a new analyst revision is recalculated/submitted.
- Publish requires `scope_count = approved_changes + approved_feasible_holds + rejected + excluded` and zero pending/conflict rows. Any full-catalog omission blocks publication. Revalidate actor separation, membership, current inputs/qualification and all review records; prices and coverage must use the same four-week period and compatible unit/currency groups.
- Publication first CAS-locks current head `{revision,proposal_hash,review_generation}` to `publishing`, reserving a deterministic pricebook ID and idempotency entry. All edits/reviews CAS the same head and fail while locked. Read the now-stable reviewed rows, build/hash immutable pricebook and coverage blobs, then transactionally finalize publication+head+event+idempotency result in the plan partition. Retries/recovery resume the same lock/version; incomplete exports are not visible as published.
- Export approved changes **and feasible approved holds** with explicit weekly schedules; rejected/excluded rows appear only in coverage with reasons. Include source plan/revision, all artifact hashes, author/reviewer/publisher, unit/currency status, price basis and scenario labels. CSV neutralizes spreadsheet formulas in free-text comments without altering numeric precision. Restore, if added later, creates a new reviewed version; never rewrite ledger history.

## Verified official SDK patterns (pin/test actual versions before implementation)

Use `ManagedIdentityCredential(client_id=...)` in Azure, avoiding fallback to an employer developer credential. Construct `BlobServiceClient(account_url, credential=credential)` and `TableServiceClient(endpoint, credential=credential)`; bind `ContainerAppsAPIClient(credential, personal_subscription_id)` explicitly. [Identity](https://learn.microsoft.com/en-us/python/api/azure-identity/azure.identity.managedidentitycredential?view=azure-python), [Blob client](https://learn.microsoft.com/en-us/python/api/azure-storage-blob/azure.storage.blob.blobserviceclient?view=azure-python), [Table service](https://learn.microsoft.com/en-us/python/api/azure-data-tables/azure.data.tables.tableserviceclient?view=azure-python), [ARM client](https://learn.microsoft.com/en-us/python/api/azure-mgmt-appcontainers/azure.mgmt.appcontainers.containerappsapiclient?view=azure-python).

Create immutable **BlockBlob** bytes via `blob.upload_blob(data, overwrite=False)`; handle existing names by validating the recorded hash. Table CAS uses `update_entity(entity, mode=UpdateMode.REPLACE, etag=etag, match_condition=MatchConditions.IfNotModified)`. Transaction updates use `("update", entity, {"mode":UpdateMode.REPLACE,"etag":etag,"match_condition":MatchConditions.IfNotModified})` inside `submit_transaction(operations)`; creates use `("create", entity)`. Never use unconditional upsert for locks/reviews. [Blob upload](https://learn.microsoft.com/en-us/python/api/azure-storage-blob/azure.storage.blob.blobclient?view=azure-python), [TableClient](https://learn.microsoft.com/en-us/python/api/azure-data-tables/azure.data.tables.tableclient?view=azure-python), [official transaction implementation](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/tables/azure-data-tables/azure/data/tables/_table_batch.py).

Start with `client.jobs.begin_start(fixed_resource_group, fixed_job_name, template=None)`; consume/persist the returned poller result/operation metadata, and reconcile with `client.jobs_executions.list(fixed_resource_group, fixed_job_name)`. REST alternative is `POST /subscriptions/{personal_id}/resourceGroups/{rg}/providers/Microsoft.App/jobs/{job}/start?api-version=2026-01-01`; HTTP 202/Location/Retry-After is acceptance, not training completion. No start idempotency guarantee is assumed. [SDK start/stop](https://learn.microsoft.com/en-us/python/api/azure-mgmt-appcontainers/azure.mgmt.appcontainers.operations.jobsoperations?view=azure-python), [execution list](https://learn.microsoft.com/en-us/python/api/azure-mgmt-appcontainers/azure.mgmt.appcontainers.operations.jobsexecutionsoperations?view=azure-python), [REST start](https://learn.microsoft.com/en-us/rest/api/resource-manager/containerapps/jobs/start?view=rest-resource-manager-containerapps-2026-01-01).

Separate API/worker managed identities: narrow Blob container and Table data roles; worker reads inputs and writes only training control/results, never identity/review/publication. API ARM custom role at the **fixed job scope** permits only required `Microsoft.App/jobs/read`, `start/action`, `executions/read`, `execution/read`, and `stop/execution/action`; no write/listSecrets/wildcards/Owner. Add environment read at its exact scope only if the chosen SDK requires it. RBAC cannot prohibit start-template overrides by itself. [Official job permission list](https://learn.microsoft.com/en-us/azure/container-apps/jobs).

## Remaining implementation questions and acceptance evidence

- Phase 2/3 owners must provide the accepted operational pipeline/evidence policy, actual cutoff-160 model status, comparison schema, cost/rule input validators, measured memory/runtime, and the bound for comparison work. Until then the corresponding route capability stays unavailable; import/read and explicit hold review remain defined.
- Before deployment: pin SDK/API versions and prove conditional Table transactions/409–412 mapping, crash recovery at Blob/head boundaries, concurrent quotas/reviews/publish, ambiguous-start fencing, no second fit, cancellation termination, image pull and least-privilege access. Finalize owner settings for upload frequency/storage retention and provider revocation handling. These are concrete implementation checks, not recurring manual permission prompts for product buttons.
- Acceptance uses **two distinct real pricing test UIDs** with private ephemeral credentials, real Firebase tokens and separate roles: permitted analyst upload/train, forbidden anonymous/uninvited/cross-workspace/self/stale actions, independent review, durable refresh/restart, once-only private publication, authorized exports, and bilingual browser errors. No reset/reuse of existing privileged demo accounts; no claim of completion from mocked identity tests.
