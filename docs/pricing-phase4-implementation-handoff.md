## Fixed dispatch binding

The controller owns a complete reviewed template: one fixed container name/image digest, command/args, resources and base environment; no init containers in v1. It validates this against deployed job configuration and the separately fixed `Job.identity`. Only server-generated `PRICING_RUN_ID`, `PRICING_RUN_GENERATION`, and `PRICING_RUN_NONCE` vary. Public schemas reject images, commands, environment fields and templates. An override replaces the whole template, so sending just the three binding variables would discard necessary configuration. [Azure override behavior](https://learn.microsoft.com/en-us/azure/container-apps/jobs#start-a-job-execution-on-demand), [SDK template fields](https://learn.microsoft.com/en-us/python/api/azure-mgmt-appcontainers/azure.mgmt.appcontainers.models.jobexecutiontemplate?view=azure-python).

Persist the immutable run binding/nonce hash, full template hash, runtime image digest and deployment/identity configuration hash before the single start POST. Keep nonce/template material private. Worker claim requires exact run+generation+nonce match and its actual `CONTAINER_APP_JOB_EXECUTION_NAME`; delayed old executions cannot claim new work. Disable transport and application start retries. Lost/ambiguous responses become `dispatch_unknown`, retaining the slot until reconciled; a valid nonce does not authorize a second start or prove an old execution stopped. Release only after every execution attributable to the dispatch is terminal and artifacts/status are finalized. See the backend contract for the same-partition transaction and SDK patterns.

This explicit binding replaces the earlier `template=None` design as a routine implementation clarification. It introduces no extra manual approval for authenticated analyst requests. Current research governance remains separate from the accepted operational training pipeline; routine output is unreviewed, and price publication still requires the normal independent human review.
