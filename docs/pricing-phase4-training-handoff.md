# Phase 4 bounded operational training handoff

Implemented 2026-11-18. This handoff records implementation and **no-fit** verification. It does not establish hosted runtime capacity, a successful real training execution, live managed-identity access, or independent scientific approval. No cloud mutations or real fits were performed by this implementation task. Frozen Phase 2/3 inference, research governance, bundle loader and pricing engine files are unchanged.

## Interfaces and authority

New modules are `pricing_web.training` (controller/ARM), `training_policy` (fixed policy and admission), `training_worker` (separate Job child), `training_supervisor` (independent parent inside the same Job), and `operational_bundle` (trusted operational inference adapter).

`TrainingService(store, blobs, config, dispatcher)` exposes:

* `admit(principal, workspace, snapshot_id, pipeline_version, idempotency_key)`; only `operational-weekly-v1` is accepted.
* `get(principal, workspace, run_id)`; read only, with actual `state`, `phase`, `completed_tasks`, `total_tasks`, and ETag.
* `cancel(...)` and `reconcile(...)`, each optionally taking the route's idempotency key. These actions preserve an operation identity and return that same run's current projection. The HTTP routes require the key. A retry can inspect/complete cancellation or reconciliation; it cannot submit another start.
* `get_model(principal, workspace, model_id)` returns actual selection/confirmation metrics, source assertions, four-week demand and baseline scenario rows, and restrictions. It does not return executable checkpoint references.
* `load_model_bundle(workspace, model_id)` is an internal authorized-resolution seam. The isolated comparison adapter uses `collect_operational_payloads(blobs, workspace, registry, run)` followed by `load_operational_payloads(payloads, registry, run)` in its child process. Additional server registry fields such as `bundle_ref` are accepted; the adapter's bundle reference is exactly the immutable result manifest reference.

The API's snapshot metadata resolves `pricing_snapshot_ref`; its blob is exactly `{schema:"pricing-snapshot-v1",identity,history,value_space}`. History hash is SHA-256 of canonical JSON history, and dataset/snapshot versions retain the existing core definitions. Original week indices, source SHA, scope, cutoff, and source-asserted currency/unit/basis remain bound. Matching item names never authorize borrowing the OJ reference model.

The API alone writes `metadata/workspace/model:{run_id}` after completed-manifest validation and positive provider termination. The worker writes private artifacts and `control/training` only. It has no identity, review, publication, or metadata-write permission. `registry_authority:"completed-operational-job-v1"` is a server record, never a public request field or a replacement for review.

## Admission, dispatch and termination

Settings, singleton slot, generation, UTC global/user counters, Run and training idempotency live in `PricingControl/training`. One conditional transaction checks settings/slot/counter ETags and creates the reservation; global ≤3/day, user ≤2/day, one active slot. Failures and ambiguous starts consume quota. Training defaults disabled unless owner configuration enables it. Kill-switch checks run again before dispatch and between worker tasks.

Admission freezes source/snapshot hashes, native units, policy/config hash, conditional trial plan, seed, core-module hashes, exact Python/ML runtime, code/lock hashes, image digest and all resource budgets in private immutable Blob before fitting. Insufficient input remains inspectable; it does not produce a fake successful model.

The controller validates the fixed deployed identity, complete template, manual trigger, retry limit zero, parallelism/completion count one, 600-second timeout, 2 vCPU and 4 GiB. It stores dispatch intent, complete template hash, deployment identity/config hash and prior execution names before its one start call. Every fixed environment value, command, args and resource value is retained. Only server-generated run ID, generation and a 256-bit nonce vary. Nonce and template artifacts stay private.

The tested package is `azure-mgmt-appcontainers==5.1.0`, whose generated operation API is **2026-07-01**; the controller pins that version explicitly. The earlier contract's 2026-01-01 REST example was not assumed to be the installed SDK version. A real SDK recording transport verifies one POST only after a simulated lost response, the explicit subscription URL, and the complete serialized template. `RetryPolicy(retry_total=0)` disables transport retries; there is no application start retry. `begin_start(..., polling=False)` captures returned execution metadata without waiting for training. Cancellation calls the installed SDK's `begin_stop_execution(..., polling=False)` after cancellation is durable.

Official references: [full override behavior](https://learn.microsoft.com/en-us/azure/container-apps/jobs#start-a-job-execution-on-demand), [execution template](https://learn.microsoft.com/en-us/python/api/azure-mgmt-appcontainers/azure.mgmt.appcontainers.models.jobexecutiontemplate?view=azure-python), [start/stop operations](https://learn.microsoft.com/en-us/python/api/azure-mgmt-appcontainers/azure.mgmt.appcontainers.operations.jobsoperations?view=azure-python), [zero-retry policy](https://learn.microsoft.com/en-us/python/api/azure-core/azure.core.pipeline.policies.retrypolicy?view=azure-python).

The worker requires the injected binding and actual `CONTAINER_APP_JOB_EXECUTION_NAME`; it atomically claims Run and slot once. It checks the complete stored template's environment against its actual environment, frozen runtime/source/config/image bindings, and repeats admission. Wrong nonce, missing execution name, duplicate claims, old generations and terminal runs cannot fit. Claims never expire or get reassigned on heartbeat loss.

Worker success leaves `phase:"awaiting_provider_terminal"` and retains the slot. Explicit reconcile POSTs inspect provider executions; all executions appearing since the pre-start inventory, including unexpected duplicates, must be positively terminal. An unknown start can be bound through a matching full execution template or an actual worker claim. Empty inventories, missing known executions, historical eviction or stale heartbeats never prove quiescence. Such cases stay fenced and require positive provider evidence; there is no unsafe force-release endpoint. Model registration and final slot release follow validation. `model_id` appears only on this finalized success. GET does no dispatch or paid work.

## Fixed operational policy and budgets

The minimum timeline is 80 weeks from first knowable observation to cutoff; selection origins are cutoff−20/−16/−12, confirmation origins cutoff−8/−4, and final refit uses the cutoff. Every block predicts four weeks. Feature time origin is the first knowable week, training origins start four weeks later and advance by four. Original calendar indices and delayed `known_at_index` visibility are preserved. There is no random split.

The frozen candidates are the unchanged `poisson-a01`, `poisson-a10` and `tree-80` parameter sets; controls are `last4mean` and `seasonal52`. Existing `training_examples`, `fit_model`, `select_candidates`, `price_qualification` and `predict_scenarios` perform the actual work. Candidate selection uses the original 2% pooled MAE gain, two winning folds and maximum 1.10 fold ratio. Confirmation can only retain or reject previously selected roles, using 2% pooled gain and maximum 1.10 ratio across both blocks. It cannot search for another model. Selected role assignment is content-hashed and durably recorded before confirmation access.

Maximum calls/tasks are:

| Stage | Model fit calls | Baseline tasks |
|---|---:|---:|
| Three selection origins | 9 | 6 |
| Two confirmation origins, deduplicated demand/price roles | ≤4 | 4 |
| Final origin, deduplicated confirmed roles | ≤2 | 2 |
| Total | **≤15** | **12** |

Maximum total tasks is 27, with actual completion count recorded. `completed_fits` counts durably reserved/completed `fit_model` calls; a constant-zero call consumes this conservative budget but records `optimizer_executed:false` and the core's zero-iteration diagnostics. Baselines never consume fit reservations. Every fit has a pre-fit durable reservation, bounded checkpoint, completion receipt, elapsed time, optimizer diagnostics, and failure state when aborted. Partial results never register a model, and no incomplete fit is resumed.

Training separately caps 300 series, 40,000 actual expanded examples, and the dense design's actual width: `10 + series_count + 2 * item_count`. Therefore 300 distinct items can require **910 features**, unlike the 265-feature OJ design. No-fit admission computes the exact rows/categories at every planned cutoff. The estimate is 512 MiB overhead + six dense design matrices + two Hessian matrices and must fit a 3 GiB worker budget. Constructed row count and width are checked again immediately before each fit. Quantity and price retain the pricing input bounds `[0,1e12]` and `[1e-6,1e9]` and must be finite.

The first fold's already planned two Poisson fits and tree fit provide actual backend profiles; there are no extra profile fits. Each must finish within 60 seconds. After both families are measured, the worker projects the remaining possible role combinations plus observed preprocessing overhead and 30 seconds of finalization headroom; it stops if the 480-second soft budget is infeasible. This is an admission/continuation estimate, not a runtime or cost guarantee.

The fixed worker entry point is now an **independent parent supervisor** launching a single fitting child inside the same Azure Job; it adds no service, sidecar or fit. Every two seconds the parent samples the entire descendant process tree's RSS and the entire job cgroup's current/peak memory, enforcing the 3 GiB budget. These are explicitly distinct measurements: summed child-tree RSS can double-count shared pages, while cgroup memory includes the supervisor, caches and all job processes. It records both along with effective CPU quota/affinity (`cpu.max` or v1 quota), rather than interpreting visible host CPU count as a 2-CPU allocation. The child still verifies a 4 GiB cgroup allocation before fitting.

The parent enforces 120 seconds per active fit, 580 seconds total, 30 seconds without non-fit progress/startup, and cancellation. The provider separately enforces 600 seconds. Bounds are sampled, with up to the two-second sampling interval before detection. The resource/deadline/kill loop performs no network calls. Its separate control I/O sampler uses only the control table, zero SDK retries and one-second connection/read timeouts; eight seconds without a fresh successful control observation fails closed even if that sampler hangs. External heartbeats retain measured progress/resource evidence. The parent kills and reaps the child tree **before** attempting bounded failure persistence; a failed record write cannot delay termination. It handles SIGTERM/SIGINT, and the child uses a Linux parent-death signal. Neither process releases the slot. A duplicate execution's supervisor cannot modify another execution's claim. CAS retries accommodate concurrent supervisor heartbeats without repeating a fit reservation.

## Result trust and product meaning

The loader validates complete schema, task counts, selection/confirmation policy, all referenced bytes/hashes, runtime/core/image/config/source identity, final model roster, exact origin/scope and native values before `joblib.load` of any checkpoint. It only deserializes the server's own content-hash bytes through `BytesIO`; it never follows a user path, network URL, class field, pickle upload, or caller's `reviewed:true`. Objects are bounded to 32 MiB and the inference inventory to 128 MiB. The adapter subclasses the unchanged `VerifiedBundle`, preserving its engine trust/type checks while overriding the native value space with the immutable uploaded-source assertion.

Demand champion and qualified price Poisson are separate roles. When no Poisson survives, the loader returns `None` for pricing, leaving the engine in rules/manual/hold mode while model views retain actual demand/baseline forecasts. Future forecasts explicitly hold the last observed price/ad for four weeks; they are assumed-condition scenarios with no validated future accuracy. Historical metrics are conditional on realized future price/ad, and Poisson fitting is quasi-likelihood for nonnegative recorded quantities. Neither is causal demand, guaranteed profit, or unknown-condition forecasting.

Every stage/result states `publication_ready:false` and `scientific_result:false`; registry status is `unreviewed_operational`. The authenticated Train button runs this fixed operational policy as an ordinary workflow. It does not claim independent scientific approval. Executable prices still require the separate human review/publication workflow.

The base environment must contain matching `PRICING_IMAGE_DIGEST`, code/lock hashes, worker-only `PRICING_MANAGED_IDENTITY_CLIENT_ID`, explicit private Blob/Table endpoints, input `PRICING_BLOB_CONTAINER` and distinct `PRICING_RESULTS_BLOB_CONTAINER`. The worker Blob client writes only results and reads only results plus inputs. Its identity needs Reader on inputs and Contributor on results, with no plans-container access; it does not construct a plans client. Recommended thread variables are fixed to two. Worker command remains exactly `python -m pricing_web.training_worker`; the parent internally launches the same module with fixed `--child` and a local supervisor PID binding. Resources remain 2 CPU/4Gi. The three run binding variables are added only by the server. No credentials or actual private resource identifiers are in this repository.

Run no-fit checks with `.venv/bin/python -m unittest discover -s tests/training -v`. **21 tests pass**, covering admission races, idempotency, quota consumption, old generations, missing/wrong nonce, duplicate claim, lost start response, one SDK POST/full template, kill switch/deployment drift/roles, cancellation and timeout terminal fencing, exact design width/PIT, invalid/short/excessive inputs, partial worker failure, mocked complete pipeline, checkpoint integrity, source mismatch and native currency preservation. Five additional real-subprocess tests verify a native GIL-holding child is killed at a shortened test fit deadline, descendant-tree allocation crosses a real RSS budget and is reaped, stalled control I/O cannot stall termination, SIGTERM is handled, and failure reporting observes the child already dead. Failure and task state are retained in the injected store while the slot stays fenced. Test budgets are fractions of seconds and use no fitting or cloud. The complete synthetic pipeline mocks every fit and checkpoint serialization; it establishes control flow, not ML quality.

Remaining acceptance is intentionally real: independent code/policy review; bounded actual first-fold backend profiles and then a complete authorized run; actual Consumption cgroup/time/memory limits and image pull; explicit personal-scope managed-identity permissions and template normalization against the deployed job; actual provider list/stop/timeout behavior, private artifact persistence and scale-to-zero recovery; authenticated upload/train/reconcile/compare from the live web app; and independent two-user price review/publication. Those checks must use the fixed predeclared budgets and retain any failure as evidence rather than silently increasing resources or retrying fits.
