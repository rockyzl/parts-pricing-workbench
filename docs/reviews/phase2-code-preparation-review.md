## Scientific checks

The target-week price and advertising columns remain explicitly conditional inputs. Origin-visible catalog construction and history/support summaries exclude later observations and delayed records. Missing target rows are excluded from scores, retained in forecast coverage, and never treated as zero sales.

The recent-mean and exact week-minus-52 baselines follow the written fallback rules. Models use the same evaluation constructor and observed-target mask. Pooled row MAE, signed error, zero-denominator WAPE, horizon and macro-series metrics follow the protocol. Selection requires the full expected candidate/fold set and uses the declared gain, fold wins, worst-fold ratio, and tie order. These are implementation checks, not evidence of predictive improvement.

The Poisson design has unscaled brand-specific log-price columns, so the extracted tail coefficients have the declared log-link association units. Tree settings explicitly disable internal early stopping. A constant-zero training state avoids calling an optimizer. Unknown/new series and stale histories retain baseline fallbacks. A synthetic arbitrary-item/site-null input works with caller-supplied training-origin metadata; the governed source loader remains pinned to OJ.

The scenario interface validates complete explicit plan membership and checks price/advertising support within the requested known advertising state. The current refit coefficient is checked separately from selection-fold stability. Scenario `price_response_eligible` remains false pending a consumer joining reviewed qualification. Any later consumer must calculate the conjunction of reviewed series eligibility, marginal price support, and joint price/ad support; a blind eligibility overwrite is not acceptable.

## Material findings and correction review

1. **Baseline refit coverage — corrected.** Initially, only learned-fit workers emitted future predictions. A baseline-only winner could therefore complete a zero-fit refit without forecasts. Both baselines now have explicit forecast artifacts, including the selected-demand flag. The independent synthetic supervisor probe verified the zero-fit branch. Real refit and complete final artifact replay remain later-phase requirements.
2. **Premature ranking — corrected for governed consumption.** Initially, the supervisor wrote `selection.json` before final cgroup, ledger, wrapper, and terminal checks. Selection now exists only inside the success terminal after outer completion checks. All governed downstream phases call the strict public validator; a failure artifact or incomplete/mutated tree makes the terminal ineligible for use. Complete production finalization remains part of the authorized real smoke.
3. **Semantic replay — corrected.** The initial `validate_run` verified inventory/report hashes without fully reconciling phase contracts, report identities, wrapper results, capacity evidence, and recomputed selection. The revised path checks the exact tree, start/proposal/decision bindings, original consumption-time chronology, report/start/cache identities, reservation/completion sequence, completion and resource evidence, result reconciliation, and selection recomputation. The synthetic replay fixture now has real-shaped historical decision bindings; no fresh execution permission is inferred from historical review validity.
4. **Transient-service lifetime.** The original command used `systemd-run --wait` and queried the service afterward. The installed `systemd-run(1)` manual states that successful transient units are unloaded immediately by default, making that final query racy. The owner replaced this with an asynchronous retained-service lifecycle. The reviewer inspected the owner's separately authorized [no-data probe evidence](../../data/model-runs/wrapper-probe-20261118/evidence-retained.json): active/exited state with MainPID 0, retained 20,959,232-byte peak, empty/collected worker group, successful release, and subsequent inactive/not-found state. This verifies the recorded infrastructure probe only; it does not verify the complete production model path or model capacity. The earlier `evidence.json` probe is not a pass because its empty-ControlGroup check was flawed. This reviewer did not launch either probe.
5. **Capacity authority and failure recording — corrected in code.** Feasibility now uses the verified retained outer aggregate peak and reconciles it with the worker snapshot and capture receipt. Status/release/cleanup waits are bounded, and cleanup exceptions are recorded without skipping the failure-artifact attempt. Actual resource limits, timings, absence of memory events, complete-worker emptiness, and successful release still require production smoke evidence.
6. **Phase-plan validation — corrected.** `validate_phase_plan` reconstructs mandatory smoke/selection/confirmation evidence, exact candidate/origin/seed roster, derived output/unit identities, deadlines, and feasibility values from phase/configuration and authenticated prior runs. Proposal validation and public replay both use it. No-fit mutations reject missing trials and enlarged budgets.
7. **Early admission — corrected.** Series admission now precedes repeated roster construction, and accumulated training rows are checked during assembly. The independent 301-series probe rejected before the roster function was invoked.
8. **Concurrent handoff visibility — corrected.** `completion.json` and `resource-capture.json` use atomic create-exclusive publication of fully written bytes. The no-fit visibility check passed. The outer observer also retries a potentially older memory-peak sample until the fixed capture deadline instead of failing solely because completion appeared after the previous status sample.
9. **Independent stale-progress detection — corrected.** The outside observer now checks supervisor progress freshness with a frozen 30-second threshold, including startup before the first progress event. The no-fit stale-progress test passed. Baseline/seasonal and model fallback counts were also added, preserving explicit coverage reporting in baseline-only confirmation.
